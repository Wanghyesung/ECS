# commit — 사용자 스타일 커밋 메시지

메시지를 지어내지 말고 **변경사항을 먼저 읽고** 쓴다. 스타일은 이 저장소 히스토리에서 추출한 것이므로 임의로 바꾸지 않는다.

## 1. 실행 환경 판단 (먼저)

- `$CLAUDE_AUTOPILOT` = `1` (밤 무인 실행) → **직접 커밋한다**. `block-git-commit` 훅이 그 프로세스에서만 꺼져 있다.
- 그 외(대화형) → 훅이 Claude의 `git commit`을 무조건 차단한다. **시도하지 말고** 완성된 메시지를 ```bash 코드블록으로 넘겨준다(사용자가 ▶ Run). settings.local.json을 고쳐 우회하지 않는다.

## 2. 변경사항 파악

```bash
git status --short
git diff --stat HEAD
git log --oneline -5
```

- 대량 변경이면 `git diff --stat`으로 영역을 먼저 잡고, 핵심 파일 몇 개만 `git diff`로 실제 내용을 본다. 추측으로 불릿을 쓰지 않는다.
- `.asset`/`.prefab`/`.unity`는 diff가 YAML이라 읽기 어렵다 — 무엇이 바뀌었는지 모르면 불릿에 "밸런스 수치 조정", "프리팹 인스턴스 추가"처럼 **확인된 수준까지만** 쓴다.
- **이 저장소는 커밋이 큰 편이다**(30~290 파일). 기능 하나가 여러 폴더에 걸쳐 있으면 억지로 쪼개지 말고 한 커밋 + 상세 불릿으로 간다. 성격이 완전히 다른 두 작업(예: 게임 기능 + 하네스 설정)이 섞였을 때만 나눌지 묻는다.

## 3. 제목

```
[태그] 한국어 요약 - 부연(선택)
```

- **태그**(실제 사용 빈도순): `[Add]` 새 기능/에셋/문서 · `[Refactor]` 동작 동일, 구조/성능 개편 · `[Fix]` 버그 수정 · `[Update]` 기존 기능 수정·수치 조정·설정 정리 · `[Remove]` 삭제 · `[Debug]` 임시 디버그. 두 성격이 겹치면 `[Fix / Add]`처럼 붙여 쓴 전례가 있으나 **하나로 고르는 쪽을 우선**한다.
- 한국어, 명사형 종결(`추가`, `수정`, `변경`, `개편`, `통일`, `적용`). "~했습니다" 금지.
- 길이 제한 없음 — 중앙값 70자, 최대 140자. 필요하면 ` - `로 부연을 붙이거나 `,`로 항목을 나열한다.
- 증상이 있는 버그는 **증상을 제목에** 쓴다. 구체적인 타입/필드명을 그대로 인용한다.

실제 예시:
```
[Add] 핵폭탄(Nuke) 레전더리 카드 - 확정 즉시 맵 전체 몬스터 처치 + 미사일 낙하 컷신
[Fix] 빌드에서 몬스터 미스폰 - SOStage가 SOPoolData 경유하도록 수정
[Refactor] ColliderManager Box 브로드페이즈를 Burst IJobParallelFor로 교체
[Update] Charge 발사 정지 처리, 몬스터/총알 밸런스 조정, git commit 방지 훅 추가
```

## 4. 본문 (기본으로 쓴다 — 최근 30개 중 27개가 본문 있음)

빈 줄 하나 뒤에 `- ` 불릿. 한 줄짜리 자명한 변경만 본문을 생략한다.

- 형식: **`- 파일/클래스: 무엇을 어떻게`**. 타입·메서드·필드명을 실제 이름 그대로 쓴다.
- 수치 변경은 `m_fRotateSpeed 20→90`, `far clip 620→1200`처럼 **화살표**로.
- 씬/프리팹/SO 변경은 **별도 불릿**으로 명시(`씬: NukeCenter 앵커 추가, 풀 데이터 2종 PoolDataList 등록`).
- 이전 커밋의 연장이면 해시를 인용한다(`직전 커밋(a535ee5)에서 ~ 하나만 고쳤던 문제를 전체로 확장`).
- 한 불릿이 길면 다음 줄에 2칸 들여쓰기로 이어 쓴다.
- "왜"가 비자명하면 한 줄 덧붙인다(`— 발사 후에도 충전 파티클이 계속 재생되던 문제 수정`).

실제 예시:
```
[Add] 핵폭탄(Nuke) 레전더리 카드 - 확정 즉시 맵 전체 몬스터 처치 + 미사일 낙하 컷신

- SOFeatureNuke: SOAttackInfo(SO_NukeAttackInfo) 기반, Apply 시 NukeStrike로 발사 위임
- NukeMissile(IAttackObject): 상공→착탄점 unscaled 낙하만 담당, 착탄 동작은 SOBulletAction 조합
  (SOKillAllMonstersAction 전체 처치 + SOSpawnExplosionAction 노란 구체 임팩트)
- CameraManager.FollowTarget 추가: 낙하 전반 미사일 추적 → 후반 맵 전경으로 후진 → 착탄 후 대기
- 씬: NukeCenter 앵커(맵 중앙 0,0,938), 카메라 far clip 620→1200, 풀 데이터 2종 PoolDataList 등록
```

## 5. Unity 주의사항 (스테이징)

- **`.meta`는 짝을 맞춰 반드시 함께** 스테이징한다. 에셋만 올리고 `.meta`를 빠뜨리면 다른 클론에서 GUID가 재생성돼 참조가 깨진다. `git status`에 에셋이 있는데 `.meta`가 없거나 그 반대면 경고한다.
- `ProjectSettings/`, `Packages/manifest.json`은 **`git add` 하지 않는다** — `bash-gate` 훅이 차단한다. 그 변경이 필요하면 사용자가 직접 확인 후 올린다.
- `.claude/state/`는 gitignore 대상이다. 올라오려 하면 무시 규칙을 먼저 확인한다.
- 파일명에 공백이 있으면 경로를 `"..."`로 감싼다(`"SO_NukeImpact Data.asset"`).
- 기본은 `git add -A`. 성격이 다른 변경이 섞여 있어 나눠야 할 때만 경로를 명시한다.

## 6. 출력

**대화형**: 메시지를 보여주고 바로 실행 가능한 한 덩어리를 준다. heredoc으로 본문 줄바꿈을 보존한다.

````
```bash
git add -A ; git commit -m "[Add] 제목" -m "- 불릿1
- 불릿2"
```
````

여러 커밋으로 나눌 때는 블록을 순서대로 나눠서 준다(한 블록에 한 커밋).

**autopilot**: 위 규칙대로 직접 커밋하고 결과 해시를 보고한다.

## 8. 하지 말 것

- 사용자가 커밋을 요청하지 않았는데 먼저 커밋하거나 스테이징하지 않는다.
- 영어 제목, 이모지, `feat:`/`fix:` 같은 Conventional Commits 형식 — 이 저장소 스타일이 아니다.
- 확인하지 않은 내용을 불릿에 쓰지 않는다. 모르면 diff를 더 본다.
- `--no-verify`, `--amend`(사용자가 명시적으로 요청한 경우 제외), force push.
