# /unity-prototype — 빠른 프로토타입

다음에 대한 플레이 가능한 프로토타입을 만듭니다: **$ARGUMENTS**

## 워크플로우

`unity-prototyper` 에이전트를 사용하여 완전하고 플레이 가능한 프로토타입을 제공합니다.

### 1단계: 분해
메커닉을 다음으로 분해합니다.
- 플레이어 시스템 (이동, 능력, 입력)
- 월드 요소 (플랫폼, 장애물, 트리거)
- 게임 규칙 (승리/패배, 점수)
- 카메라 동작

### 2단계: 스크립트 작성
최소한의 기능적인 C# 스크립트를 작성합니다.
- `[SerializeField]` 파라미터를 노출한 플레이어 컨트롤러
- 게임 메커닉 (물리, 트리거, 점수)
- 프로토타입 설계 원칙을 따릅니다: **깔끔함보다 기능성**

### 3단계: MCP로 씬 구성
속도를 위해 `batch_execute`를 사용합니다.
1. `Prototype_[MechanicName]`이라는 이름의 새 씬을 생성합니다
2. 모든 게임오브젝트를 생성합니다 (플레이어, 환경, 장애물, 카메라)
3. 컴포넌트를 추가하고 구성합니다 (Rigidbody, Collider, Renderer)
4. 물리 레이어와 충돌 매트릭스를 설정합니다
5. 플레이어를 따라가도록 Cinemachine 카메라를 구성합니다

### 4단계: 검증
- `read_console`을 통해 콘솔에 오류가 없는지 확인합니다
- 완성된 프로토타입 설정을 사용자에게 보고합니다

### 5단계: 보고
사용자에게 다음을 알립니다.
- **조작법** — 어떤 키/버튼을 사용하는지
- **생성된 스크립트** — 파일 이름과 위치
- **씬** — 이름과 여는 방법
- **조정 가능한 값** — 조정할 SerializeField 파라미터
- **다음 단계** — 더 완전한 프로토타입을 위해 추가할 사항

## 6단계: 자동 검증 (선택 사항)

프로토타입이 완성된 후, `unity-verifier` 에이전트 실행을 제안합니다.
- 모든 프로토타입 스크립트에 대한 심각한 문제의 빠른 검토
- 직렬화 안전성, null 체크, 성능 문제를 자동으로 수정
- 아키텍처 관련 사항은 건너뜁니다 (프로토타입은 구조보다 속도를 우선시합니다)

다음과 같이 제안합니다: "프로토타입 준비 완료! 빠른 검증 과정을 실행해 드릴까요?"

## 설계 규칙
- 10분 목표 — 그보다 오래 걸린다면 과도하게 만들고 있는 것입니다
- 플레이스홀더 비주얼 — 색이 입혀진 기본 도형, 아트 작업 불필요
- 모든 것을 조정 가능하게 — Header가 있는 SerializeField
- 단일 씬 — 프로토타입에는 멀티 씬을 사용하지 않습니다
- UI 없음 — 피드백에는 Debug.Log와 Gizmos를 사용합니다
