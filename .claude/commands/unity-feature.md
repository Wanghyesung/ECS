# /unity-feature — 기능 구현

사용자가 설명한 기능을 계획하고 구현합니다: **$ARGUMENTS**

## 에이전트 라우팅

- 기본값: `unity-coder` 에이전트 사용(opus — 완전한 아키텍처적 추론)
- `$ARGUMENTS`에 `--quick`이 포함된 경우: `unity-coder-lite` 에이전트 사용(sonnet — 단순 추가 작업을 위한 더 빠른 처리)
- 에이전트에 전달하기 전에 인자에서 `--quick` 플래그를 제거합니다.

## 1단계: 계획

1. **기능을 분석**합니다 — 어떤 Unity 서브시스템이 관련되는지 식별합니다:
   - 입력 시스템? 물리? 애니메이션? UI? 오디오? 네트워킹?
   - 기존의 어떤 스크립트/시스템과 통합되는지?

2. **필요한 스크립트를 식별**합니다 — 새로 만들 스크립트와 수정할 기존 스크립트를 파악합니다.

3. **씬 변경 사항을 식별**합니다 — 어떤 GameObject, 컴포넌트, 씬 설정이 필요한지 파악합니다.

4. 구현하기 전에 사용자에게 **계획을 제시**합니다. 다음을 포함합니다:
   - 생성/수정할 스크립트
   - MCP를 통한 씬 변경 사항
   - 기존 시스템에 대한 종속성
   - 예상 복잡도(간단 / 보통 / 복잡)

## 2단계: 구현

1. `unity-coder` 에이전트를 사용하여 **C# 코드를 작성**합니다:
   - `.claude/rules/`의 모든 규칙을 준수합니다.
   - 올바른 어셈블리 정의에 스크립트를 배치합니다.
   - 인스펙터 구성을 위해 `[SerializeField]`를 사용합니다.
   - 정리를 위해 `[Header]` 속성을 추가합니다.

2. MCP를 통해 **씬 요소를 설정**합니다:
   - `batch_execute`로 GameObject 생성
   - 컴포넌트 구성
   - 필요한 경우 물리 레이어 설정

3. `read_console`을 통해 컴파일 오류가 있는지 **콘솔을 확인**합니다.

## 3단계: 검증

1. `read_console`을 통해 콘솔 오류가 없는지 확인합니다.
2. 생성/수정된 내용을 요약합니다.
3. 기능을 테스트하는 방법을 설명합니다.
4. 필요한 수동 단계가 있으면 언급합니다(예: 인스펙터에서 참조 할당).
5. 더 좋은 기능이 있는지 확인합니다.

## 4단계: 자동 검증(선택 사항)

구현 후, 검증-수정 루프를 위해 `unity-verifier` 에이전트 실행을 제안합니다:
- 직렬화 안전성, 성능, Unity 관련 함정에 대해 변경된 모든 파일을 검토합니다.
- 안전한 문제(누락된 FormerlySerializedAs, CompareTag, 캐시되지 않은 GetComponent 등)를 자동으로 수정합니다.
- 최대 3회 반복하여 깨끗해질 때까지 재검증합니다.
- 사람의 판단이 필요한 남은 항목을 보고합니다.
