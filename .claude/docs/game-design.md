**한 줄 요약:** 짧고 반복 가능한 던전 런 위에, 레벨업 3택과 등급형 조커 카드 도박이라는 이중 랜덤을 얹은 하이 리스크·하이 리턴 빌드업 슈터.

몰려오는 몬스터를 자동·반자동 사격으로 정리하며 던전을 반복 클리어하는 슈팅에, 두 겹의 랜덤 성장 시스템을 얹었다. 레벨업마다 3개 중 1개를 고르는 익숙한 빌드업 위에, 조커 카드 도박이라는 별도의 하이 리스크 계층을 더해 — 안전하게 쌓을지, 더 좋은 카드를 노리고 지금까지 모은 것을 걸지 매 판 다시 선택하게 만드는 것이 이 게임의 정체성이다.

## 기획 의도 · 차별점 — 이중 랜덤 구조

궁수의 전설·뱀서라이크류의 "레벨업 3택"은 이미 익숙한 재미다. 이 게임은 그 위에 등급형 도박 카드(조커 카드)를 얹어 랜덤성을 한 겹 더 쌓는다.

- **레벨업 3택** — 안전한 성장. 몬스터를 잡아 경험치를 채우면 확정적으로 카드 3장 중 1장을 고른다.
- **조커 카드 도박** — 선택적 고위험 성장. 플레이어가 원할 때 도전하는 확률형 잭팟. 연속 성공할수록 후보 등급(일반→희귀→에픽)과 골라 담을 수 있는 개수가 함께 오르지만, 실패하면 그동안 쌓아온 카드(보류분 + 이미 적용된 기능)를 잃는다.

"한 번 더 걸어볼까, 지금 여기서 멈출까"라는 긴장이 매 레벨업마다 반복되는 것이 이 게임의 감정 설계 핵심이다.

시장 방향성: 복잡하고 진입 장벽이 높은 게임이 많은 시장에서, 직관성과 단순함이 주는 본질적인 재미에 집중한다. 배우는 데 시간이 들지 않고, 한 판이 짧게 끝나며, 매번 다른 조합으로 다시 하고 싶어지는 게임이 목표다.

## 핵심 루프

```
로비 → 던전 입장 → 전투 (스테이지 순차 진행) → 레벨업 3택 / 조커 도박 →
보스 처치 → 클리어 or 사망 → 다음 런
```

`DungeonManager`가 `List<SOStage>`를 순서대로 진행한다. 각 스테이지는 시간표 기반 스폰 테이블(몇 초 뒤 어떤 몬스터를 어디에)을 가지고 있고, 그 스테이지의 몬스터를 모두 처치하면 다음 단계로 넘어간다. 전투 중 경험치가 쌓여 레벨이 오르면 `BattleManager`가 카드 선택 UI(`CardCreator`)를 띄워 진행을 잠시 멈추고 3택을 제시한다.

한 판(런)은 자원을 영구히 들고 나가는 구조가 아니라, 매 런마다 레벨업 3택과 조커 도박으로 그 판의 빌드를 새로 쌓는 방식이다 — 매번 다른 조합이 나오는 재미가 반복 플레이 동기다.

| 유형 | 설명 |
|------|------|
| Bullet | 기본 직선 탄 |

탄 이동은 `BulletMoveManager` / `JobBullet`이 `TransformAccessArray` + Burst Job으로 대량 처리하도록 이미 구현되어 있어, 화면을 채우는 탄막을 전제로 설계되어 있다.


## 성장 시스템 — 레벨업 3택

```
EXP 누적 → Max 도달 → 레벨업 → 기능 카드 3개 제시 → 1개 선택 → 즉시 적용
```

몬스터를 처치하면 `BattleManager`에 경험치가 쌓이고, Max Exp에 도달하면 레벨이 오르며 `FeatureManager.RequestFeature`가 후보를 뽑아 제시한다. 후보는 가중치 기반 무작위 추첨(각 카드의 `Weight` 값에 비례)이며, 이미 최대 레벨에 도달했거나 1회성인데 이미 획득한 카드는 후보 풀에서 자동으로 제외된다.

### 현재 구현된 카드 목록

| 분류 | 카드 |
|------|------|
| 기본 스탯 강화 | 체력 증가(UpHP) · 공격력 증가(UpAttack) · 방어력 증가(UpDefense) · 이동속도 증가(UpSpeed) · 탄속 증가(UpBulletSpeed) |
| 전투 로직 강화 | 공격속도 증가(AttackSpeedUp) · 관통(Penetration) · 명중 시 효과 추가(AddHitAction) · 도착 시 효과 추가(AddArriveAction) |
| 무기 확장 | 무기 추가(AddWeapon) · 드론 추가(AddDrone) |

카드마다 등급(Tier), 획득 방식(반복 가능 / 1회성), 최대 레벨을 데이터로 가지고 있어 밸런스 조정은 코드 수정 없이 SO 값 변경만으로 가능하다.

### 등급

| 등급 | 비고 |
|------|------|
| Common | 기본 등급 |
| Uncommon | |
| Rare | |
| Epic | |
| Legendary | 최상위 등급 — 조커 카드 도박에서 조커 레벨이 오를수록 등장 비중이 커짐 |

## 조커 카드 도박 (핵심 차별점)

레벨업 3택이 "안전한 성장"이라면, 조커 카드는 플레이어가 스스로 판을 키우는 "선택적 도박"이다. 연속 성공할 때마다 후보 등급과 선택 폭이 함께 커지지만, 단 한 번의 실패로 그동안 쌓아온 것을 잃을 수 있다.

### 흐름

```
도전(RollGamble) → 확률 판정 → 성공: 조커 레벨 +1, 후보 노출
                              → 실패: 보류 카드 + 기존 획득 카드 몰수(CancelFeature)
```

성공하면 즉시 적용되지 않고 보류(Pending) 목록에만 담긴다. 플레이어는 보류 상태에서 한 번 더 도전(누적)하거나, 지금까지 고른 것을 확정(캐시아웃, `PickData`)해 실제 `FeatureManager`에 적용할 수 있다. 실패하는 순간 보류 목록은 전부 사라지고, 조커 레벨에 비례해 이미 확정된 카드까지 무작위로 잃을 수 있다(`GetLostCount`).

방향성 (실제 수치 미정 — 아래 "밸런싱 데이터" 참고):

| 조커 레벨 | 성공률 | 후보 구성 |
|-----------|--------|-----------|
| Lv 0 | 높음 | 후보 소량 · 대부분 Common |
| Lv 1–2 | 중간 | 후보 증가 · Uncommon/Rare 비중 ↑ |
| Lv 3+ | 낮음 | Epic/Legendary 개방 · 실패 시 손실 폭도 최대 |

### 데이터 구조 (`SOJokerCard` — 전부 `AnimationCurve`)

| 커브 | X축 | Y축 |
|------|-----|-----|
| `m_refSuccessChance` | 현재까지 연속 성공 횟수(조커 레벨) | 다음 도박 성공 확률 (0~1) |
| `m_refCandidateCount` | 조커 레벨 | 그 회차에 보여줄 후보 카드 수 |
| `m_refPickCount` | 조커 레벨 | 그중 실제로 고를 수 있는 카드 수 |
| `m_refLostCardCoun` | 조커 레벨 | 실패 시 잃을 카드 수 (보류분 + 기확정분 포함) |
| `m_arrTierWeight[등급]` | 조커 레벨 | 해당 등급 `SOFeature.Weight`에 곱할 배율 |

런타임 상태(현재 조커 레벨, 보류 카드 목록)는 SO가 아니라 `JokerCardManager`가 들고 있어 — 여러 플레이어/런이 같은 `SOJokerCard` 에셋을 공유해도 데이터가 오염되지 않도록 설계되어 있다 (`architecture.md`의 데이터 분리 규칙과 일치).

## 던전 & 몬스터

### 던전 진행

`DungeonManager`가 스테이지를 순서대로 진행한다. 각 `SOStage`는 "몇 초 뒤 어떤 몬스터를 어디에" 스폰할지 목록(`ListSpawnEntry`)과 보스 정보(`BossPrefab`, `BossSpawnPosition`)를 갖는다. 설계는 마지막 스테이지에서만 보스가 등장하고, 그 전 스테이지는 일반 몬스터를 다 잡으면 보스 없이 바로 다음 스테이지로 넘어가는 것이다.

### 몬스터 AI

프로젝트 필수 아키텍처(Behavior Tree + SO Action + Blackboard, `architecture.md` 참고)를 그대로 따른다. `Monster`가 `BehaviorTree`와 `BlackBoard`를 들고 매 프레임 `m_refBT.Evaluate(blackboard)`로 갱신하며, 이동/추적/조준/발사/대기 등 25종 이상의 BT 노드(`SOTraceNode`, `SOFireRadialDirNode`, `SOChargeFireNode` 등)가 구현되어 있다. 사망 시 `Monster.OnMonsterDied` 정적 이벤트로 EXP 보상을 알리고, 넉백/상태이상은 전투 시스템 절을 그대로 재사용한다.

## 범위

### Does — 이미 구현되어 있음

- 스테이지 순차 진행형 던전 런 (스폰 테이블 + 보스)
- 레벨업 3택 성장 (가중치 기반 카드 추첨, 등급/최대레벨/1회성 제약)
- 조커 카드 도박 (도전 → 성공 시 보류 누적 → 캐시아웃 or 실패 시 몰수)
- 4슬롯 장비, 5종 스탯
- BT 기반 몬스터, 상태이상(DoT 포함), 넉백
- Burst Job 기반 대량 탄막 이동, 오브젝트 풀링

### Does NOT — 범위 밖

- 멀티플레이
- 메타 진행 (런 밖으로 들고 나가는 영구 재화·해금)

## 밸런싱 데이터 — 미정

조커 카드 도박의 5개 곡선(성공 확률, 후보 수, 선택 수, 손실 수, 등급별 가중치)과 레벨업 3택 각 카드의 추첨 가중치·최대 레벨은 방향성(레벨이 오를수록 성공률↓, 보상 폭↑)만 정해졌고 구체 수치는 미정이다.

## 엣지 케이스

| 케이스 | 실제 코드 동작 |
|--------|-----------------|
| 레벨업 후보가 요청 개수보다 적게 남음 | `RequestFeature`가 있는 만큼만 반환 (부족분은 호출부에서 빈 슬롯 처리) |
| 1회성 카드를 이미 획득 | 후보 풀에서 자동 제외 |
| 카드가 최대 레벨(`MaxLevel`) 도달 | 후보 풀에서 자동 제외 (0이면 무제한) |
| 레벨이 한 번에 여러 번 오름 (몬스터 다수 동시 처치) | `CoLevelUP`이 보류된 레벨업 수만큼 카드 선택을 순차 재생 (한꺼번에 뭉개지지 않음) |
| 조커 도박 실패 | 보류 카드 전부 몰수 + `GetLostCount`만큼 이미 확정된 기존 카드도 무작위로 추가 몰수 |
| 조커 레벨 0에서 몰수당할 기존 카드가 하나도 없음 | `CancelFeature`가 보유 목록이 비면 그대로 반환 (예외 없음) |
| 몬스터 사망 시점에 이미 Dead 상태 | `TakeDamage`가 Dead 상태면 조기 반환해 중복 사망 처리 방지 |
| 넉백 도중 다시 피격 | 진행 중이던 넉백 코루틴을 멈추고 새 넉백으로 교체 |

## 인수 조건

1. 몬스터를 처치해 EXP가 Max Exp 이상 쌓이면 레벨이 오르고 카드 3장이 제시된다.
2. 제시된 3장 중 1장을 고르면 즉시 플레이어에게 효과가 적용되고 나머지 2장은 사라진다.
3. **(부정 테스트)** 1회성(`OneTime`) 카드를 한 번 획득한 뒤에는 이후 어떤 레벨업/조커 후보에도 다시 등장하지 않는다.
4. 조커 카드 도박에 성공하면 조커 레벨이 1 오르고, 다음 도전의 성공 확률·후보 등급 구성이 곡선에 따라 달라진다.
5. **(부정 테스트)** 조커 카드 도박에 실패하면 보류 중이던 카드는 전부 사라지고, 아직 "캐시아웃"하지 않은 성공은 어떤 영구 효과도 남기지 않는다.
6. 보류 카드를 캐시아웃하면 그 순간 `FeatureManager`에 실제로 적용되고, 조커 레벨은 0으로 초기화된다.
7. 한 스테이지의 일반 몬스터를 모두 처치하고 `BossPrefab`이 설정되어 있으면, 해당 위치에 보스가 스폰된다.
8. 보스를 처치하면 다음 스테이지의 스폰 테이블이 예약되고, 마지막 스테이지의 보스를 처치하면 던전 클리어로 처리된다.
9. **(성능)** 탄막이 화면을 가득 채우는 상황(동시 활성 탄 다수)에서도 60FPS 이상을 유지한다.
10. **(부정 테스트)** 몬스터가 이미 Dead 상태일 때 추가 피격 판정이 들어와도 EXP가 중복 지급되지 않는다.
