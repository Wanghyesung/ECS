# $workflow_view

기능 범위가 크거나 코드·씬·데이터 계약을 함께 결정해야 할 때 사용한다. 사용자의 기존 승인 범위를 먼저 확인한다.

## 1. 조사

- `rg`로 유사 구현과 관련 메서드·필드를 찾는다.
- Update/FixedUpdate의 실행 빈도, 할당, 캐시 비용을 확인한다.
- ScriptableObject와 이벤트로 확장할 지점을 확인하되 불필요한 추상화는 만들지 않는다.
- 실제 씬 인스턴스와 프리팹 구성을 필요한 범위에서 확인한다.

## 2. 리뷰할 계획

`.codex/docs/prd/<feature>.md`에 목적, 범위, 사용자 흐름, 수용 기준, 영향을 받는 파일, 기존 코드 재사용 근거, 호출·상태 흐름(Mermaid), 성능·직렬화 영향, 검증 방법을 작성한다. 프로젝트 기획 문서가 있으면 대상 프로젝트의 문서를 따로 읽고 필요한 내용만 인용한다.

요구사항이나 계획에 승인되지 않은 결정이 남으면 구체적인 문서를 보여주고 그 결정에 대한 입력을 받는다. 이미 승인된 계획은 다시 승인받지 않는다.

## 3. 구현과 검증

- 승인 범위의 파일만 수정한다. 씬·프리팹·SO는 Unity MCP를 사용한다.
- `$unity-workflow`로 컴파일, 관련 EditMode/PlayMode 테스트, 필요한 독립 리뷰를 수행한다.
- 결과를 PRD에 기록한다. 테스트 불가나 수동 작업도 명시한다.

## 4. 게시

대상 프로젝트가 PR 게시 절차를 별도로 정했으면 그 절차를 따른다. 이 템플릿만으로 커밋·push·PR·메시지 전송 권한이 생기지 않는다. 게시 설정이 없으면 로컬 검토 결과와 변경 파일을 사용자에게 제공한다.
